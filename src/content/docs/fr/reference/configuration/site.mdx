Décrit l’installation domestique et ses appareils, et régule la puissance disponible.

Pour réguler la charge avec le surplus solaire, un compteur lisible placé directement après le point de raccordement au réseau est nécessaire. Vous pouvez en outre indiquer des appareils pour la production solaire et la ou les batteries domestiques. Les puissances de plusieurs appareils sont additionnées automatiquement et, pour les batteries domestiques, le niveau de charge moyen est calculé.

**Par exemple** :

```yaml
site:
  title: Home # display name for UI
  meters:
    grid: mygridmeter # grid meter reference
    pv:
      - mypv1 # first pv meter reference
      - mypv9 # second pv meter reference
    battery:
      - mybat5 # battery meter reference
    aux:
      - myaux1 # self-regulating consumer
    consumer:
      - myconsumer1 # regular consumer, recorded for consumption statistics
    ext:
      - myext1 # for data logging, load management, etc.
  curtailers:
    - my_curtailer # curtailment device reference
  residualPower: 100
```

---

## Paramètres obligatoires

### `title`

La désignation du point de charge est également affichée dans l’interface.

**Par exemple** :

```yaml
title: Home
```

---

### `meters`

Définit le rôle de chaque compteur configuré (appareil de mesure), c.-à-d. le point de mesure auquel il correspond. Cela relie logiquement la définition de l’appareil à son usage prévu. Un compteur générique au départ reçoit ainsi une fonction selon son emplacement dans l’installation domestique.

:::note
La configuration d’au moins un élément `grid` ou d’au moins un élément `pv` est nécessaire !

evcc ne peut pas être utilisé sans au moins l’une de ces entrées !
:::

**Par exemple** :

```yaml
site:
  meters:
    grid: mygridmeter # grid meter reference
    pv: mypv1 # pv meter reference
    battery: mybat2 # battery meter reference
    aux: myaux1
```

---

## Paramètres facultatifs

### `meters.grid`

Définit le [`meter`](/fr/reference/configuration/meters) (appareil de mesure) qui fournit les mesures au point de raccordement au réseau.

**Valeurs possibles** : valeur d’un paramètre `name` dans la configuration [`meters`](#meters).

**Par exemple** :

```yaml
grid: mygridmeter # grid meter reference
```

---

### `meters.pv`

Définit les [`meter`](/fr/reference/configuration/meters) (appareils de mesure) auprès desquels evcc récupère les mesures de la production solaire.
Plusieurs appareils peuvent être indiqués. Les puissances sont additionnées automatiquement.

**Valeurs possibles** : une valeur unique ou une liste de valeurs d’un paramètre name dans la configuration [`meters`](#meters). La forme en liste peut aussi être utilisée avec une seule valeur.

**Par exemple** :

```yaml
pv: myonlypv # single pv meter reference
```

ou

```yaml
pv: # (pvs = deprecated)
  - myoldpv # first pv meter reference
  - mynewestpv # second pv meter reference
```

---

### `meters.battery`

Définit les [`meter`](/fr/reference/configuration/meters) (appareils de mesure) qui fournissent les mesures de la ou des batteries.
Plusieurs appareils peuvent être indiqués. Les puissances sont additionnées automatiquement et une moyenne est calculée à partir du niveau de charge des batteries.

**Valeurs possibles** : une valeur unique ou une liste de valeurs d’un paramètre `name` dans la configuration [`meters`](#meters). La forme en liste peut aussi être utilisée avec une seule valeur.

**Par exemple** :

```yaml
battery: myonlybat # single battery meter reference
```

ou

```yaml
battery: # (batteries = deprecated)
  - mysmallbat # first battery meter reference
  - myhugebat # second battery meter reference
```

### `meters.aux`

Compteurs d’appareils externes qui effectuent leur propre régulation du surplus mais ne sont pas pilotés directement par evcc, p. ex. un thermoplongeur autorégulé. Leur puissance compte dans le surplus disponible pour la charge des véhicules, en partant du principe que l’appareil réduit sa consommation quand evcc attribue cette puissance à la charge. Plusieurs compteurs sont additionnés.

**Valeurs possibles** : une valeur unique ou une liste de valeurs d’un paramètre `name` dans la configuration [`meters`](#meters). La forme en liste peut aussi être utilisée avec une seule valeur.

**Exemple** :

```yaml
aux: myaux # single aux meter reference
```

ou

```yaml
aux:
  - myaux1 # first aux meter reference
  - myaux2 # second aux meter reference
```

### `meters.consumer`

Compteurs de consommateurs ordinaires comme un lave-linge ou un lave-vaisselle, enregistrés uniquement pour les statistiques de consommation. Contrairement à `aux`, cette puissance n’entre pas dans le surplus disponible pour la charge des véhicules.

**Valeurs possibles** : une valeur unique ou une liste de valeurs d’un paramètre `name` dans la configuration [`meters`](#meters). La forme en liste peut aussi être utilisée avec une seule valeur.

**Exemple** :

```yaml
consumer: myconsumer # single consumer meter reference
```

ou

```yaml
consumer:
  - myconsumer1 # first consumer meter reference
  - myconsumer2 # second consumer meter reference
```

### `meters.ext`

Compteurs qui ne servent pas à la régulation et ne sont pas affichés dans l’interface, p. ex. des tableaux divisionnaires ou des compteurs alternatifs pour le réseau ou le solaire. Leurs données sont uniquement journalisées et exportées, sans entrer dans le surplus ni dans les statistiques de consommation.

**Valeurs possibles** : une valeur unique ou une liste de valeurs d’un paramètre `name` dans la configuration [`meters`](#meters). La forme en liste peut aussi être utilisée avec une seule valeur.

**Exemple** :

```yaml
ext: myext # single ext meter reference
```

ou

```yaml
ext:
  - myext1 # first ext meter reference
  - myext2 # second ext meter reference
```

### `curtailers`

Appareils de bridage issus de la configuration [`curtailers`](/fr/reference/configuration/curtailers) qui limitent l’export vers le réseau à la demande du gestionnaire de réseau (§ 9 EEG).
Ils s’appliquent en même temps que les compteurs `pv` bridables lorsque l’intégration [`hems`](/fr/reference/configuration/hems) signale une limite.

**Valeurs possibles** : une liste de valeurs d’un paramètre `name` dans la configuration [`curtailers`](/fr/reference/configuration/curtailers).

**Exemple** :

```yaml
curtailers:
  - my_curtailer # curtailment device reference
```

### `residualPower`

Définit le point de fonctionnement visé par la régulation du surplus au point de raccordement au réseau (compteur avant réseau). La valeur par défaut est 0 W.
Les valeurs positives déplacent la consigne du côté de l’export vers le réseau, les valeurs négatives du côté de l’import du réseau.
Au final, cette valeur fixe l’« état de repos » de la boucle de régulation, que le régulateur doit ajuster.

En particulier avec d’autres systèmes de régulation du surplus indépendants, comme une batterie domestique, cette valeur doit être ajustée pour que le système se comporte de façon prévisible, avec des priorités claires.

Si une certaine part d’import du réseau doit subsister ou être autorisée en mode Intelligent, vous pouvez configurer une valeur négative correspondant à la part maximale d’import du réseau.

#### `grid` `meter` présent

- Valeur positive : puissance d’export vers le réseau restante
- Valeur négative : puissance d’import du réseau restante

#### Seul un `pv` `meter` présent

- Valeur positive : consommation domestique typique, utilisée pour estimer le surplus solaire.
- Valeur négative : la puissance indiquée est ajoutée à la puissance solaire et augmente la puissance de charge disponible (attention : import du réseau)

:::note
Si une batterie domestique est présente, il est fortement recommandé d’indiquer ici une petite valeur, p. ex. entre 100 et 300 W, afin de permettre la charge de la batterie selon les priorités configurées (voir `prioritySoc`). Sinon, la régulation indépendante de la batterie domestique ne verra aucun surplus utilisable. Cela évite également un import temporaire du réseau, même sans batterie, lors de variations rapides de la production et de la consommation.
:::

**Exemple « Batterie domestique »** :

```yaml
residualPower: 100
```

**Exemple « Part d’import du réseau »** :

La charge doit démarrer en mode Intelligent avec au moins 6 A (monophasé) même avec seulement 50 % de surplus solaire (le reste venant du réseau).
Puissance de charge minimale : 1 phase × 6 A × 230 V = 1 380 W, dont 50 % : 690 W

Voir aussi l’[alternative avec enable/disable pour autoriser une part de solaire et d’import du réseau](/fr/features/solar-charging).

```yaml
residualPower: -690
```
