Quelque chose ne fonctionne pas comme prévu ?
Un bon rapport contient une description claire, votre configuration et un journal qui montre le problème.
Cette page indique où signaler un problème et comment rassembler ces informations.

## Pourquoi un bon rapport est important \{#why\}

Chaque installation est différente.
Les appareils, les versions de firmware, les paramètres et le réseau varient d’un foyer à l’autre.
Nous sommes une communauté d’utilisateurs et de développeurs qui s’entraident.
Nous aimerions vous aider vous aussi, mais nous ne pouvons pas voir votre système.
Votre rapport est notre seule fenêtre sur celui-ci.

Avec une description, la configuration et un journal qui montre le problème, nous trouvons souvent la cause dès la première réponse.
Un rapport précis nous permet aussi de reproduire un bug, et c’est ce dont nous avons besoin pour le corriger.
Les autres personnes qui ont le même problème en profitent aussi, car elles trouvent votre message et sa solution.

## Avant de signaler un problème \{#checklist\}

- **Mettre à jour** : utilisez la dernière version. Pour les bugs, vérifiez avec la dernière version nightly, car le problème y est peut-être déjà corrigé.
- **Rechercher** : consultez les [discussions](https://github.com/evcc-io/evcc/discussions), les [issues](https://github.com/evcc-io/evcc/issues) et la [FAQ](/fr/faq), y compris les messages fermés. Si votre problème y figure déjà, ajoutez vos détails à ce message.
- **Reproduire** : déclenchez à nouveau le problème et notez l’heure. Vous en avez besoin pour trouver les entrées de journal correspondantes.
- **Isoler** : mettez en pause les automatisations externes (p. ex. Home Assistant, Node-RED, ioBroker). Deux systèmes qui pilotent le même appareil sont souvent à l’origine du problème.
- **Cibler** : signalez un seul problème par message.

## Où signaler le problème ? \{#where\}

- **[evcc-io/evcc](#app)** : dépôt principal pour la charge, les appareils, les tarifs et l’interface web
- **[evcc-io/app](https://github.com/evcc-io/app/issues/new/choose)** : app iOS et Android, si tout fonctionne dans le navigateur web
- **[evcc-io/docs](https://github.com/evcc-io/docs/issues/new/choose)** : documentation sur [docs.evcc.io](https://docs.evcc.io). Les pages d’appareils sont générées à partir du dépôt principal. Le lien _Modifier cette page_ en bas de chaque page mène à la bonne source.
- **[evcc-io/evcc.io](https://github.com/evcc-io/evcc.io/issues/new/choose)** : site [evcc.io](https://evcc.io), p. ex. fautes de frappe
- **[evcc-io/optimizer](https://github.com/evcc-io/optimizer/issues/new/choose)** : optimiseur, si les résultats calculés sont invraisemblables ou inattendus

Les problèmes liés à l’image Linux relèvent de [evcc-io/images](https://github.com/evcc-io/images/issues/new/choose), ceux liés à l’app Home Assistant de [evcc-io/hassio-addon](https://github.com/evcc-io/hassio-addon/issues/new/choose).

## Discussion ou bug ? \{#type\}

- **[Discussion](https://github.com/evcc-io/evcc/discussions)** : questions et aide pour votre installation. La plupart des comportements inattendus s’avèrent être une question de configuration ou de paramètres.
- **Bug** : quelque chose fonctionnait auparavant et a cessé de fonctionner après une mise à jour, ou le comportement contredit clairement la documentation. Les bugs se signalent sous forme d’[issue](https://github.com/evcc-io/evcc/issues).

Si vous ne pouvez pas exclure un problème de paramétrage, commencez par une discussion.

## Signaler depuis l’interface web \{#app\}

La page **Signaler un problème** rassemble pour vous la version, le système, la configuration et les journaux.
Elle crée une discussion ou une issue préremplie sur GitHub.
Vous avez besoin d’un [compte GitHub](https://github.com/signup) pour cela.

<Steps>

1. Ouvrez **Plus → Signaler un problème**.

2. Sélectionnez **J’ai besoin d’aide avec mon installation** ou **J’ai trouvé un bug**.

3. Remplissez **Titre**, **Description** et **Étapes permettant de reproduire le problème**.
   Décrivez ce que vous attendiez et ce qui s’est passé à la place.

4. Vérifiez les **Informations additionnelles**.
   Pour les **Journaux**, cliquez sur les paramètres et choisissez le niveau, le nombre de lignes et les zones.
   Pour des périodes plus longues, [enregistrez un journal](#logs) et joignez-le sous forme de fichier.
   N’incluez l’**Etat** que si quelqu’un le demande.

   <Screenshot
     name="report-a-problem/report-a-problem"
     caption="Page Signaler un problème avec la description et les informations additionnelles"
   />

5. Cliquez sur **Créer un problème sur GitHub…** ou **Démarrer une discussion sur GitHub…**.

6. Si les informations additionnelles sont trop longues pour un lien, la boîte de dialogue affiche deux étapes.
   Créez d’abord le message sur GitHub.
   Revenez ensuite à votre instance, cliquez sur **Copier les informations additionnelles** et collez-les dans le message à l’emplacement indiqué.
   Sans cette deuxième étape, votre message ne contient ni configuration ni journaux.

</Steps>

Si vous rédigez le message à la main sur GitHub, vous pouvez copier chaque section de cette page individuellement avec **copier**.

:::caution[Les rapports sont publics]
Nous remplaçons automatiquement les mots de passe, les jetons et les autres valeurs sensibles par `*****`.
Vérifiez que votre message ne contient pas de données personnelles avant de le publier sur GitHub.
:::

## Enregistrer un journal \{#logs\}

La page Journaux enregistre toujours tous les niveaux, y compris `trace`.
Vous n’avez besoin ni de modifier la configuration ni de redémarrer.

<Steps>

1. Ouvrez **Plus → Journaux**.

2. Sélectionnez le niveau **TRACE** et les zones du point de charge et des appareils concernés.

   <Screenshot
     name="report-a-problem/logs"
     caption="Page Journaux filtrée sur le niveau TRACE et la zone lp-1"
   />

3. Reproduisez le problème.
   Pour les problèmes de connexion (p. ex. OCPP, EEBUS, Modbus), redémarrez d’abord votre instance afin que le journal couvre tout depuis le début.

4. Cliquez sur le bouton de téléchargement juste après l’apparition du problème.
   Le fichier contient les entrées du niveau et des zones sélectionnés.

5. Joignez le fichier à votre message sur GitHub par glisser-déposer.

</Steps>

Le journal commence avant que le problème ne survienne et se poursuit jusqu’à ce qu’il soit visible.
Il montre ainsi comment le problème est apparu.

La page Journaux conserve les 10 000 dernières entrées, soit environ 30 à 90 minutes selon votre installation.
Un redémarrage les efface.
Pour des périodes plus longues, utilisez les [journaux à long terme](#system-logs).

La page Journaux affiche par défaut le niveau `debug`, qui couvre les décisions de la boucle de régulation.
`trace` y ajoute la communication brute avec les appareils et les services.

## Journaux à long terme \{#system-logs\}

La page Journaux couvre une fenêtre limitée.
Si vous avez besoin de plus de données, d’une période plus longue ou d’entrées antérieures à un redémarrage, utilisez les journaux de votre système.
Ce sont aussi eux qu’il faut utiliser lorsque l’interface web n’est pas accessible.

Ces journaux ne contiennent que les entrées du niveau configuré, `info` par défaut.
Augmentez le niveau avant de reproduire le problème.

### Augmenter le niveau de journalisation \{#log-level\}

Le niveau se règle dans le fichier de configuration `evcc.yaml`, de manière générale et par zone.
L’exemple règle `debug` de manière générale et `trace` pour le premier point de charge.
Vous trouverez les noms de vos zones dans le filtre par zone de la [page Journaux](#logs).

```yaml title="evcc.yaml"
log: debug
levels:
  lp-1: trace
```

Si le fichier n’existe pas encore, créez-le avec ces seules lignes.
La configuration effectuée dans l’interface web reste inchangée.
Remettez le niveau à sa valeur précédente une fois le journal obtenu, car `trace` génère beaucoup de données.

### Journaux selon l’installation \{#platforms\}

L’emplacement des journaux et le fichier à modifier dépendent de la manière dont vous avez installé evcc.
Ouvrez le panneau correspondant à votre installation.

<details>
<summary>Raspberry Pi et autres cartes (image Linux evcc)</summary>

Ouvrez [Cockpit](/fr/installation/linux-image#cockpit) à l’adresse `https://evcc.local:9090`.
Modifiez les fichiers avec **Navigateur** et exécutez les commandes dans **Terminal**.

Pour augmenter le niveau de journalisation, modifiez `/etc/evcc.yaml` et redémarrez :

```sh
sudo systemctl restart evcc
```

Afficher les entrées de la dernière heure :

```sh
sudo journalctl -u evcc --since "1 hour ago" --no-pager
```

Suivre le journal en direct :

```sh
sudo journalctl -fau evcc
```

Afficher une plage horaire :

```sh
sudo journalctl -u evcc -S "2026-03-21 07:00" -U "2026-03-21 08:00" --no-pager
```

Copiez la sortie du terminal dans votre message.

</details>

<details>
<summary>Docker</summary>

Pour augmenter le niveau de journalisation, ajoutez-le à votre `compose.yml` si vous utilisez Docker Compose, ou au fichier `evcc.yaml` que vous avez monté dans le conteneur.

<Tabs>
  <TabItem label="compose.yml">

    ```yaml
    services:
      evcc:
        environment:
          - EVCC_LOG=debug,lp-1:trace
    ```

    Recréez le conteneur :

    ```sh
    docker compose up -d
    ```

  </TabItem>
  <TabItem label="evcc.yaml">

    ```yaml
    log: debug
    levels:
      lp-1: trace
    ```

    Redémarrez le conteneur :

    ```sh
    docker restart evcc
    ```

  </TabItem>
</Tabs>

Afficher toutes les entrées du conteneur nommé `evcc` :

```sh
docker logs evcc
```

Suivre le journal en direct :

```sh
docker logs -f --since 10m evcc
```

Afficher les entrées de la dernière heure :

```sh
docker logs --since 1h evcc
```

Copiez la sortie du terminal dans votre message.

Avec Docker Compose, utilisez `docker compose logs evcc` dans le dossier de votre `compose.yml`.
Les interfaces Docker (p. ex. Synology, QNAP, Portainer, Unraid) affichent le journal dans les détails du conteneur.
Recréer le conteneur supprime son journal.
Pour conserver les journaux de façon permanente, consultez la documentation de votre interface Docker.

</details>

<details>
<summary>Home Assistant</summary>

Pour augmenter le niveau de journalisation, modifiez `/addon_configs/49686a9f_evcc/evcc.yaml`.
Dans l’onglet **Configuration** de l’app, `config_file` doit être défini sur `/config/evcc.yaml`.
Redémarrez ensuite l’app.
Consultez [Fichier de configuration](/fr/installation/home-assistant) pour savoir comment modifier le fichier.

Pour obtenir les journaux, ouvrez **Paramètres → Applications → evcc** dans Home Assistant et sélectionnez l’onglet **Journal**.

</details>

<summary>Linux</summary>

Pour augmenter le niveau de journalisation, modifiez `/etc/evcc.yaml` et redémarrez :

<details>
<summary>macOS</summary>

Si vous avez installé evcc avec Homebrew et configuré l’agent launchd comme décrit sous [macOS](/fr/installation/macos), le journal est écrit dans un fichier.

Pour augmenter le niveau de journalisation, modifiez `/etc/evcc.yaml` et redémarrez :

```sh
launchctl kickstart -k gui/$(id -u)/io.evcc
```

Afficher les journaux :

```sh
tail -f "$(brew --prefix)/var/log/evcc.log"
```

</details>

<details>
<summary>FreeBSD</summary>

Pour augmenter le niveau de journalisation, modifiez `/usr/local/etc/evcc.yaml` et redémarrez :

```sh
service evcc restart
```

Suivre le fichier journal :

```sh
tail -f /var/log/evcc.log
```

</details>

<details>
<summary>Windows</summary>

Pour augmenter le niveau de journalisation, modifiez le fichier `evcc.yaml` situé dans le dossier de `evcc.exe` et redémarrez le service.
Le service doit être lancé avec l’argument `-c evcc.yaml`.

Les fichiers journaux n’existent que si vous avez configuré la redirection de sortie dans l’onglet **I/O** du [service en arrière-plan](/fr/installation/windows#nssm).
Sans service, lancez le programme dans une fenêtre de terminal pour voir la sortie.

</details>

## Demandes de fonctionnalités \{#feature-request\}

Il manque un appareil ou une fonctionnalité ?
La communauté est grande, il y a donc de bonnes chances que quelqu’un ait déjà eu une idée similaire.
Prenez un peu de temps pour faire des recherches avant de soumettre votre demande sous forme d’[issue](https://github.com/evcc-io/evcc/issues/new/choose).

- **Rechercher** : consultez les [discussions](https://github.com/evcc-io/evcc/discussions) et les [issues fermées](https://github.com/evcc-io/evcc/issues?q=is%3Aissue+is%3Aclosed) pour voir si le sujet a déjà été abordé.
- **Relancer un sujet est permis** : les circonstances ont peut-être changé depuis la dernière fois que le sujet a été abordé.
- **Quoi et pourquoi** : décrivez ce que vous souhaitez obtenir, pas seulement la solution que vous avez en tête.
- **Nouveaux appareils** : indiquez le modèle exact de l’appareil et joignez la documentation de l’API ou la fiche technique fournie par le fabricant. Soyez prêt à tester et vérifier avec votre propre appareil.
