evcc est développé par la communauté.
La plupart des façons d’aider ne demandent aucune ligne de code.

## Commencer petit \{#start}

Ne commencez pas par la grande fonctionnalité qui vous tient à cœur, même si les agents d’IA rendent cela incroyablement simple et tentant.
Lisez d’abord les [discussions](https://github.com/evcc-io/evcc/discussions) et les [issues](https://github.com/evcc-io/evcc/issues) pour vous faire une idée du fonctionnement de la communauté.
Votre idée a probablement déjà été évoquée, alors recherchez-la et rejoignez la conversation existante.
Commencez par quelque chose de petit et progressez à partir de là.
Les changements plus importants doivent faire l’objet d’un accord dans une issue ou une discussion avant de passer à l’implémentation et à une pull request.

## Aider les autres \{#help}

Beaucoup de questions dans les [discussions](https://github.com/evcc-io/evcc/discussions/categories/need-help) peuvent être résolues par quelqu’un qui possède le même appareil ou a eu le même problème.
Le tri aide aussi : reproduire les bugs signalés, demander les journaux manquants et signaler les doublons.
[Signaler un problème](/fr/report-a-problem) explique ce que contient une issue utile.

## Tester les nouvelles versions \{#testing}

La version nightly contient tout ce qui a été fusionné depuis la dernière version publiée.
Tous les guides d’installation (p. ex. [Linux](/fr/installation/linux), [Docker](/fr/installation/docker) ou [Home Assistant](/fr/installation/home-assistant)) expliquent comment y passer.
Sauvegardez votre installation avant de changer de version.
Les nouvelles fonctionnalités sont souvent d’abord expérimentales et doivent être activées dans **Configuration → Expérimental**.

Pour une pull request, les mainteneurs peuvent publier un build de test avec des binaires et une image Docker `evcc/evcc:pr-<number>`.
Un court rapport de test de quelqu’un qui dispose du matériel correspondant est souvent ce qui permet de fusionner une modification.
Si une pull request n’a pas encore de build de test mais que vous pourriez la tester, n’hésitez pas à en demander un dans la pull request.

Pour essayer en avant-première les nouvelles versions de l’app iOS et Android, consultez la [section bêta de l’app](https://github.com/evcc-io/app#beta-testing).

## Vos propres appareils \{#devices}

Les meilleures premières contributions viennent de votre propre installation.
Vous possédez un onduleur, une batterie domestique, un véhicule ou un chargeur que les mainteneurs ne peuvent pas tester.
Confirmez que des corrections fonctionnent ou améliorez les instructions d’un modèle d’appareil.
Votre appareil n’est pas encore pris en charge ? Configurez-le d’abord comme [appareil personnalisé](/fr/user-defined-devices) puis, une fois qu’il fonctionne, transformez-le en modèle d’appareil pour tout le monde.

## Traduire \{#translate}

L’interface est traduite sur [Weblate](https://hosted.weblate.org/engage/evcc/).
Ajoutez une nouvelle langue ou vérifiez et améliorez une traduction existante, sans aucun outil de développement.

## Améliorer la documentation \{#docs}

Chaque page comporte en bas un lien **Modifier cette page** qui vous mène à sa source sur GitHub.
La documentation est rédigée en anglais et en allemand.
Si vous ne parlez qu’une de ces deux langues, indiquez-le dans votre pull request et nous vous aiderons pour l’autre.

## Écrire du code \{#code}

Le [guide de contribution](https://github.com/evcc-io/evcc/blob/master/CONTRIBUTING.md) couvre les règles de base, l’environnement de développement et la manière de tester en local.
Les sujets généraux de développement sont discutés sur [Slack](https://evcc.io/slack).

## Développer autour d’evcc \{#build}

Les tableaux de bord, écrans, utilitaires ou gadgets matériels qui aident d’autres utilisateurs sont aussi des contributions.
L’[API REST](/integrations/rest-api) et l’[API MQTT](/fr/integrations/mqtt-api) vous donnent accès à toutes les données de votre instance evcc.
Présentez votre projet dans les discussions et ajoutez-le aux [autres projets géniaux](/fr/smarthome/awesome).

## Jetons de contributeur \{#token}

Le projet vit des contributions de nombreuses personnes : code, modèles, documentation, traductions, réponses dans les discussions ou rapports de test détaillés.

Vous avez déjà pas mal contribué ? [Envoyez-nous un court e-mail](mailto:info@evcc.io) avec votre nom d’utilisateur GitHub et nous vous attribuerons un jeton de parrain illimité.
