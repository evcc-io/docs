Ein Fahrzeug steht für ein bestimmtes Elektrofahrzeug mit seiner Batterie. Wenn ein Fahrzeug konfiguriert und einem [Ladepunkt](/de/reference/configuration/loadpoints#vehicle) zugewiesen ist, kann die Oberfläche den Ladestatus, den Ladestand, die verbleibende Ladezeit und weitere Daten anzeigen, die automatisch vom Fahrzeug abgerufen und verarbeitet werden.

In der Oberfläche kannst du die Ladung außerdem auf einen bestimmten Ladestand begrenzen. Da die meisten Wallboxen den Ladestand des Fahrzeugs nicht kennen können (er wird nur bei ganz bestimmten Kombinationen aus Wallbox und Fahrzeug übermittelt), kann evcc mit dieser Konfiguration direkt über die Online-Schnittstelle (API) des Fahrzeugherstellers mit dem Fahrzeug kommunizieren.

Die `vehicles`-Konfiguration ist eine Liste von verschiedenen Fahrzeugen.

**Beispiel**:

```yaml
vehicles:
  - name: Zoe
    type: ...
    ...
```

Konfigurationen für bekannte Fahrzeuge findest du unter [Geräte – Fahrzeuge](/de/vehicles).

Im Folgenden werden die verschiedenen Parameter erklärt.

---

## Erforderliche Parameter

### `name`

Eine Kurzbezeichnung des konfigurierten Fahrzeugs. Der Wert wird verwendet, um das Fahrzeug in der Konfiguration des [Ladepunkts](/de/reference/configuration/loadpoints#vehicle) zu referenzieren.

**Beispiel**:

```yaml
name: zoe
```

---

### `title`

Eine Beschreibung des Fahrzeugs, die in der Oberfläche angezeigt wird.

**Beispiel**:

```yaml
title: Zoe
```

---

### `type`

Dies ist der evcc-Schnittstellentyp, über den die Kommunikation mit dem Fahrzeug läuft. Bekannte Fahrzeuge können über den Typ `template` eingebunden werden. Den passenden (Template-)Typ für bekannte Fahrzeuge und Hinweise zur benutzerdefinierten Konfiguration mit `custom` findest du unter [Geräte – Fahrzeuge](/de/vehicles).

---

## Optionale Parameter

### `capacity`

Die nutzbare Kapazität der Fahrzeugbatterie in Kilowattstunden (kWh).

Wird verwendet, um den Energiebedarf für die Ladeplanung zu berechnen.

**Beispiel**:

```yaml
capacity: 50 # kWh
```

---

### `phases`

Die _maximale_ Anzahl an Phasen, die dieses Fahrzeug nutzen kann (ggf. inkl. Ladekabel). Der interne Standardwert ist 3. Mögliche Werte sind 1, 2 oder 3.

Manche Fahrzeuge, v. a. Plug-in-Hybride, nutzen nicht die maximal möglichen 3 Phasen zum Laden. Zwar kann `evcc` die tatsächlich genutzten Phasen bei Beginn eines Ladevorgangs ermitteln, sofern ein Ladezähler eingebaut ist, vor dem Ladebeginn steht diese Information aber nicht zur Verfügung. Ist `phases` am Fahrzeug gesetzt, kann `evcc` den Ladevorgang im Smart-Modus bereits bei geringerer verfügbarer Leistung starten.

**Beispiel**:

```yaml
phases: 2
```

---

### `cache`

Wie lange evcc abgerufene Fahrzeugdaten zwischenspeichert und erneute Anfragen an die Fahrzeugdatenschnittstelle (API) zurückhält.

:::note
Der Wert muss mit angehängter Zeiteinheit angegeben werden (siehe Beispiel). `m` steht für Minuten.
:::

:::caution
Es wird **NICHT** empfohlen, die Standardeinstellungen zu ändern, denn das könnte dazu führen, dass der Fahrzeughersteller die Ladesteuerung über evcc aktiv unterbindet. **AUF EIGENES RISIKO.**
:::

Um aktuelle Zustandsdaten vom Fahrzeug zu ermitteln (z. B. den Ladestand der Fahrzeugbatterie), wird regelmäßig die Online-Schnittstelle des Herstellers abgefragt. Damit die Server des Fahrzeugherstellers nicht ständig mit Anfragen überhäuft werden (das kann zur Sperrung des Kontos führen), ist ein Zwischenspeicher (Cache) implementiert, der diese Anfragen abfängt und mit den zuletzt abgerufenen Daten bis zu dem hier angegebenen maximalen Alter beantwortet. Da die meisten Fahrzeuge ihre Daten nur während eines laufenden Ladevorgangs und dann in sehr großen Abständen aktualisieren (10 bis 30 Minuten sind üblich), bringen häufigere Anfragen keinen Mehrwert.

**Standardwert**: `15m`

**Beispiel**:

```yaml
cache: 5m
```

---

### `identifiers`

Eine Liste mit einer oder mehreren Kennungen, um das Fahrzeug zu identifizieren. Soll das Fahrzeug an unterschiedlichen Wallboxen identifiziert werden, können mehrere Kennungen nötig sein. Die Erkennung kann über folgende Mechanismen erfolgen:

#### RFID

Verfügt die Wallbox über eine RFID-Schnittstelle, kann einem Fahrzeug eine RFID-Karte zur Identifikation zugewiesen werden. In diesem Fall wird die `RFID Token ID` benötigt.

**Beispiel**:

```yaml
identifiers:
  - 12345ABC # RFID-Kennung
```

Hinweis: Falls die Kennung als Zahl interpretiert werden könnte, muss sie in Anführungszeichen stehen.

**Beispiel**:

```yaml
identifiers:
  - "012345"
  - "12345e2"
  - "0x1234"
```

#### Fahrzeugkennung

Wenn die Wallbox es unterstützt, empfängt sie vom Fahrzeug eine Fahrzeugkennung. Das kann entweder die MAC-Adresse des On-Board-Ladegeräts sein oder eine Kennung eines fest installierten Plug-&-Charge-Zertifikats (ein anderes Zertifikat als beim DC-Laden!).

**Beispiel**:

```yaml
identifiers:
  - 01:23:45:67:89:0A # MAC-Adresse
```

Manche Fahrzeuge erzeugen jeden Tag eine neue MAC-Adresse. In diesem Fall kannst du Platzhalter verwenden, wenn sich die vorhandenen Fahrzeuge im unveränderlichen Teil der MAC-Adresse unterscheiden.

```yaml
identifiers:
  - 01:23:45:*
```

### `features: ["coarsecurrent"]`

Kennzeichnet, dass ein Fahrzeug nicht mit stufenloser Strombegrenzung geregelt werden kann.

Diese Einstellung sollte für folgende Kombination genutzt werden:

- Fahrzeug kann nur in ganzen Ampere-Schritten regeln
- Wallbox kann feiner aufgelöste Ladestromvorgaben (z. B. 1 mA) verarbeiten

In dieser Kombination kann es vorkommen, dass Änderungen von wenigen mA bei der Regelung zu einer unerwarteten Änderung des Phasenstroms um 1 A führen. Die Regelung kann dann ins Schwingen geraten. Dieser Parameter beschränkt die Regelung ebenfalls auf grobe 1-A-Schritte.

Es kann NICHT in Verbindung mit einem Fahrzeug-Template genutzt werden. Dazu muss das Fahrzeug als nativer Typ konfiguriert sein.

**Beispiel**:

```yaml
features: ["coarsecurrent"]
```

---

### `icon`

Fahrzeuge können in der Oberfläche mit verschiedenen Icons angezeigt werden. Zur Verfügung stehen:

- car
- bike
- scooter
- moped
- motorcycle
- van
- bus
- tractor
- generic
- heater
- cooler
- waterheater

**Beispiel**:

```yaml
icon: heater
```
